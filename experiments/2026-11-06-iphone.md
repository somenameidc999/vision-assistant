## Failures and changes

The original iOS 26 minimum excluded this phone. Availability guards now retain the existing behavior on iOS 16.6. Rotation uses AVFoundation portrait orientation on iOS 16.6 and rotation coordinators on newer systems. Speech permission uses the appropriate API for each OS.

The first launch required developer-certificate trust on the phone. The legacy LLDB `safequit` path also failed to keep the app running reliably. The installer now separates installation from standalone launch and verifies the resulting process. It reports a manual-open step if the optional standalone launcher is absent.

The phone could not resolve its original Tailscale hostname. A LAN proxy now forwards to the localhost backend through the Mac's specific private Wi-Fi address. Mac-side tests returned 200 for health, 401 without authentication, 201 for authenticated session creation, and 204 for deletion. The phone reached the backend in subsequent sessions. Tailscale HTTPS remains optional; its phone-side route is not independently verified.

The initial audio-route handler ended sessions on routine route changes. Capture now starts on the main actor. Routine route notifications settle before format checks, and a stopped engine can restart if its input format remains valid. True interruptions retain explicit resume. Numeric diagnostics confirmed incoming buffers, a running engine, and speech-detector activity. The user subsequently reported that spoken interaction appeared to work.

App reinstalls left backend sessions open and reached the four-session cap. Restarted this demo backend without changing the ledger or spending limit. The app now records only a pending session UUID per endpoint and cleans up that session after relaunch. Successful cleanup clears its record; a late old cleanup cannot clear a new record.

## Requested interface revision

The user requested live words and a full-screen camera. The camera now fills the screen behind compact conversation and icon controls. English partial recognition requires permission and on-device support. The recognition request sets `requiresOnDeviceRecognition = true`; no cloud Speech fallback is implemented. A prebuffer preserves the beginning of a question. Partial text stays local and is replaced by the model's returned transcript. Spoken questions still use the original audio-to-OpenRouter path.

Sanitized device diagnostics showed partial and final recognition results. The user confirmed that the live words and full-screen camera view look good. An intentional recognition finish does not show a temporary-failure banner just because recognition reports an error afterward.

Intermittent stale-view errors also exposed timestamp truncation and frame selection before cancellation completed. The app now preserves milliseconds, aligns capture times to the backend clock, and requests a fresh frame after cancellation. One stale validation rejection can refresh and retry without a second model charge. The two-second freshness rule remains unchanged.
